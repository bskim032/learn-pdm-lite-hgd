## EXPLAIN

### 1. 한 번의 튐은 노이즈, 꾸준한 상승이 신호

원본 덱 오늘의 메시지 ③: "한 번의 튐(노이즈)이 아니라 추세적 상승이 진짜 신호다. 임계선을 향해 꾸준히 오르는 흐름의 시작점을 잡으면 고장 전 계획 정비가 가능하다." (Main p2)

| | 노이즈 — 무시 | 추세 — 신호 |
|---|---|---|
| 모양 | 한 번 튀고 곧 정상으로 돌아오는 일시적 값 | 임계선을 향해 꾸준히 오르는 흐름 |
| 원인 | 측정 오류·순간 외란일 수 있다 | (원본 덱: 진동은 베어링·회전체 마모, 온도는 마찰·과부하·윤활 부족 — Main p13) |
| 정비 | 한 점의 이상치는 정비 신호가 아니다 | 상승의 시작점이 "고장 전 계획 정비"의 기준점 |

(Main p14)

### 2. 왜 기준선으로 판정하는가

원본 실습은 평상 범위(평균 ± 2표준편차)로 이상 후보를 먼저 표시한다(Main p19). 그런데 원본 정답 메모는 "설비B의 14~20번째 시점의 완만한 상승은 ±2σ에 잡히지 않는다 — 한 점이 아니라 흐름이 신호"라고 적는다. 상승분이 평균과 σ를 끌어올려 범위가 넓어지기 때문이다. 그래서 이 실습은 원본 보충교재(learn-auto-pdm)의 규칙으로 추세 시작을 잡는다.

| 단계 | 규칙 |
|---|---|
| 기준선 | 설비·센서마다 처음 12점(08:00~11:40) — 정상 운전 구간의 평균과 σ |
| 상한 | 기준선 평균 + 3σ |
| 추세 | 상한을 **3번 연속** 넘으면 추세, 그 첫 점이 추세 시작 = 정비 필요 시점 |
| 노이즈 | 상한을 넘었지만 연속 3번이 안 되면 노이즈 |

### 3. 케이스 — 데이터가 사고를 막다

원본 덱의 케이스: 한 제조사가 설비 진동 데이터를 상시 감시하다 평소와 다른 미세한 진동 증가를 포착해 고장 직전 부품을 교체했다. 그대로 뒀다면 라인 정지·부품 파손으로 며칠치 생산 손실이 났을 상황이었다 (Main p8). 오늘의 설비B가 바로 그 "미세한 증가"를 보여 준다.

## EXECUTE

아래 프롬프트를 붙여 넣으라고 안내한다.

```
data/Day5_설비센서_50건_가상.csv 로 노이즈와 추세를 판정하고 그래프 한 장을 만들어 줘.
1. 설비A 진동(mm/s), 설비B 진동(mm/s), 설비B 온도(℃) 세 계열마다
   처음 12점(08:00~11:40)으로 평균과 표준편차를 구하고
   기준선 상한 = 평균 + 3 × 표준편차 를 계산해 줘.
2. 상한을 3번 연속 넘으면 "추세"(첫 점의 시각 = 추세 시작),
   넘었지만 연속 3번이 안 되면 "노이즈", 한 번도 안 넘으면 "정상"으로 판정해 줘.
3. 결과를 outputs/trend.csv 로 저장해 줘.
   열: 설비 | 항목 | 기준선 상한 | 상한 초과 점 수 | 판정 | 추세 시작
4. kma-pdm-lite/index.html 에 선 그래프 한 장을 만들어 줘 (Chart.js).
   - 왼쪽 축: 설비A 진동 · 설비B 진동 (mm/s), 오른쪽 축: 설비B 온도 (℃) + 온도 기준선 상한(점선)
   - 두 축 모두 0에서 시작, 제목은 결론 한 줄, 그래프 아래에
     "실습용 가상 데이터 · 출처: keerhee/kma-auto-genai-3-1 data/Day5 · 2026-09-15 08:00~16:00, 20분 간격" 표기
5. 판정 결과를 표로 보여 주고 index.html을 브라우저로 열어 줘.
하지 말 것: data 원본을 고치지 않는다. 원인을 단정하지 않는다(추정은 "추정"으로).
```

### 확인할 것 (Phase B)

`~/kma-pdm-lite/outputs/trend.csv`와 `index.html`을 직접 읽어 확인한다.

- 설비A 진동: 상한 초과 1점(12:40의 3.5) → 노이즈
- 설비B 온도: 기준선 상한 57.0 ℃, 추세 시작 13:00
- 설비B 진동: 추세 시작 15:00 — 온도가 진동보다 먼저 반응했다
- `index.html`에 그래프 한 장, 두 축 0 시작, "실습용 가상 데이터" 표기

숫자가 다르면 바로 정답을 주지 말고 이 프롬프트를 붙여 넣게 한다.

```

'3번 연속' 규칙을 하나씩 다시 확인하고 어디가 달랐는지 한 줄씩 설명해 줘.

## QUIZ

```json
AskUserQuestion({
  "questions": [{
    "question": "두 설비의 진동 기록이다. 설비A: 1.0 → 1.1 → 0.9 → 3.5 → 1.0, 설비B: 1.0 → 1.3 → 1.7 → 2.2 → 2.9 (mm/s). 다음 주 계획 정비를 한 대만 잡을 수 있다면?",
    "header": "Quiz 1",
    "options": [
      {"label": "설비A — 최고값 3.5가 더 높다", "description": "한 번이라도 가장 높았던 설비를 먼저 본다"},
      {"label": "설비B — 꾸준히 오르는 추세다", "description": "임계선을 향해 계속 오르는 흐름을 신호로 본다"},
      {"label": "둘 다 아니다 — 평균이 비슷하다", "description": "평균을 비교해 판단한다"}
    ],
    "multiSelect": false
  }]
})
```

정답: 2번. 설비B는 매번 오르며 임계선을 향해 가는 추세적 상승이고, 그 상승의 시작점이 정비 신호다(Main p14·p27). 설비A의 3.5는 한 번 튀고 곧 1.0으로 돌아온 노이즈다 — 원본 모범답안은 "한 번 높았으니 위험"을 노이즈와 추세를 혼동한 감점 포인트로 든다(Main p27). 평균은 흐름을 지워 버려 추세를 보여 주지 못한다. 현장에서는 경보 한 번에 바로 정비를 잡기보다, 상한을 연속으로 넘는지 보고 계획 정비 시점을 정한다.
