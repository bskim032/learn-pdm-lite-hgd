# Block 2: 공개 — 대시보드를 GitHub Pages로

> **Phase A 시작 시 그대로 출력한다:**
> ```
> 📖 GitHub Pages 빠른 시작: https://docs.github.com/ko/pages/quickstart
> 📖 GitHub CLI 로그인: https://cli.github.com/manual/gh_auth_login
> ```

## EXPLAIN

### 1. 용어

| 용어 | 뜻 |
|---|---|
| **GitHub 저장소** | 폴더 하나를 인터넷에 올려 이력과 함께 보관하는 곳 |
| **GitHub Pages** | 저장소의 `index.html`을 `https://<아이디>.github.io/<저장소>/` 주소의 웹 페이지로 보여 주는 기능 |
| **public** | 주소를 아는 누구나 볼 수 있다 — 한 번 올린 내용은 지워도 남아 있을 수 있다 |

### 2. 왜 공개하는가

| 기준 | 그래프 파일을 메신저로 보내기 | 주소로 공개하기 |
|---|---|---|
| 대조 | 받은 사람이 숫자를 내 것과 맞춰 보기 어렵다 | 같은 주소를 보며 "13:00이 맞나" 바로 대조한다 |
| 갱신 | 고칠 때마다 다시 보낸다 | 다시 올리면 같은 주소가 바뀐다 |

### 3. 공개 전 점검 (보안 수칙)

- 그래프 아래에 "실습용 가상 데이터"와 출처가 있는가
- 회사 설비 데이터·사내 수치·개인정보가 폴더에 없는가
- 비밀번호·토큰을 입력칸에 붙여 넣지 않는다. GitHub 로그인은 브라우저에 **일회용 코드**를 입력해 승인한다

## EXECUTE

아래 프롬프트를 붙여 넣으라고 안내한다.

```
kma-pdm-lite 의 index.html 을 GitHub Pages로 공개해 줘.
1. GitHub 로그인을 확인하고, 안 되어 있으면 브라우저 로그인용 일회용 코드만 알려 줘.
2. 공개 전 점검: 폴더에 회사 데이터·개인정보·비밀값이 없는지, index.html에
   "실습용 가상 데이터" 표기가 있는지 확인해 결과를 보여 줘.
3. 점검 결과를 보여 준 뒤, public 저장소 pdm-lite-dashboard 를 만들어 올려도 되는지 나에게 먼저 물어 줘.
4. 내가 승인하면 git으로 커밋하고 푸시한 뒤, main 브랜치 루트로 GitHub Pages를 켜 줘.
5. 대시보드 주소를 알려 주고, 열리면 그래프가 보이는지 확인해 줘.
하지 말 것: 내 승인 없이 공개하지 않는다. 비밀번호·토큰을 묻지 않는다.
```

사람이 직접 하는 일:

1. 일회용 코드가 나오면 브라우저에서 https://github.com/login/device 를 열어 코드를 입력하고 **Authorize** 를 누른다.
2. 공개 전 점검 결과를 읽고 Claude의 질문에 승인 여부를 답한다.

### 확인할 것 (Phase B)

`gh repo view`와 Pages 주소로 직접 확인한다.

- 저장소 `pdm-lite-dashboard`가 있고 `index.html`이 올라가 있다
- Pages 주소가 열리고 그래프 한 장과 "실습용 가상 데이터" 표기가 보인다(처음 켜면 1~2분 걸릴 수 있다)

막히면 "Pages 주소가 안 열린다. 원인과 해결을 한 줄씩 설명한 뒤 고쳐 줘"를 붙여 넣게 한다.
